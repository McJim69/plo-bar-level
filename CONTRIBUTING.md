# 🤝 Contributing to Barangay Level Organization System

We welcome contributions to improve the **Barangay Level Organization System**.  
Please follow these guidelines to ensure smooth collaboration.

---

## 🛠 How to Contribute

1. **[Fork the repository](ca://s?q=How_to_fork_a_repository)**  
   Create your own copy to work on.

2. **[Create a feature branch](ca://s?q=How_to_create_a_feature_branch)**  
   Use descriptive names (e.g. `feature/voter-tagging-enhancement`).

3. **[Commit changes](ca://s?q=Best_practices_for_git_commits)**  
   Write clear, concise commit messages.

4. **[Push to your fork](ca://s?q=How_to_push_to_git_fork)**  
   Keep your branch updated with the latest main branch.

5. **[Open a Pull Request](ca://s?q=How_to_open_a_pull_request)**  
   Explain your changes and reference related issues.

---

## 📐 Code Style

- Follow **PSR‑4 standards** for PHP.  
- Use **secure coding practices** (parameterized queries, password hashing).  
- Keep **README and documentation updated** when adding new features.  
- Ensure **Bootstrap and custom CSS** remain consistent across pages.  

---

## 🧪 Testing

- Test changes locally before submitting.  
- Verify database migrations and backups.  
- Ensure voter tagging and hierarchy features remain functional.  

---

## 🐞 Reporting Issues

- Use the **[issue tracker](ca://s?q=How_to_use_issue_tracker)** for bugs, feature requests, or questions.  
- Provide detailed steps to reproduce problems.  
- Include screenshots or logs when possible.  

---

## 📜 Code of Conduct

All contributors are expected to follow the **[Code of Conduct](ca://s?q=View_Code_of_Conduct_in_README)** to maintain a welcoming and collaborative environment.

---

## ✅ Checklist Before Submitting

- [ ] Code compiles without errors.  
- [ ] Database changes documented.  
- [ ] README/QUICKSTART updated if needed.  
- [ ] Tests passed locally.  
- [ ] Pull request description is clear.  

---

Thank you for helping improve the **Barangay Level Organization System**! 🎉
